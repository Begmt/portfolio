## Изменения

| Before | After |
|---|---|
| Начальное сворачивание кейсов зависело от отложенного initCaseCards после DOMContentLoaded. До него браузер мог раскладывать подробное содержимое всех карточек. | В существующий head-скрипт добавлен класс `.js`, и стили закрытых кейсов применяются ещё до разбора body. Интерактивность/ARIA/inert кейсов инициализируются в основной стартовой группе. |
| Содержимое закрытых карточек оставалось участником работы отрисовки, хотя было свёрнуто и недоступно. | `.js .case-card:not(.expanded) .case-expand-inner` получает `content-visibility:hidden`. При раскрытии правило перестаёт действовать. |
| Браузер также рассчитывал дальние разделы и карточки до того, как они понадобятся посетителю. | Проекты, слоган, экосистема, сравнение процесса, ROI, workflow, профиль, контакты и отдельные карточки используют `content-visibility:auto` с приблизительными измеренными высотами и запоминанием реального размера через `auto`. Hero отрисовывается полностью. В печати и без JS отложенная отрисовка отключена. |
| Изменение размеров отложенных секций влияло на расчёт длинного якорного перехода. | Перед переходом из навигации, палитры или по начальному hash подготавливаются секции и карточки до целевой включительно. Панель сценариев сразу занимает окончательное место, чтобы её позднее появление не сдвигало якорь на 128 px. Нативные hash/история и плавная прокрутка сохранены. |
| Без JS подробные кейсы должны оставаться видимыми. | Класс `.js` отсутствует при отключённом JS; полный контент остаётся доступным. Видимые тексты, метрики и контакты сохранены. |
| Обновление навигации читало размеры после изменения стилей; при scrollY=0 размеры вообще не требуются. | В `script.js` геометрия читается перед записями и только при ненулевой прокрутке. |
| Моноширинные шрифты обнаруживались из CSS; defer-скрипты объявлялись в конце документа. | В `index.html` добавлен preload двух используемых Geist Mono; три defer-скрипта перенесены в head с сохранением порядка. |
| Hero typewriter менял textContent каждый кадр и повторно рассчитывал текст. | `interactions.js` проявляет полный доступный текст через ступенчатый clipPath; `style.css` задаёт fit-content/max-width. При reduce/скрытой вкладке эффект завершается. |
| Наблюдатели находились внутри отложенных секций уже при загрузке. | Начальные наблюдатели анимаций, счётчиков, схемы и слогана следят за внешними секциями; потомки подключаются при приближении. Существующие reveal-цели, включая карточки/шаги, сохранены. |
| Закрытый details с длинными листингами участвовал в расчёте геометрии, вкладки кода создавались сразу. | В `style.css` закрытый `.code-inspector` явно скрывает `.terminal-window`; в `interactions.js` вкладки и автодемо инициализируются один раз при первом раскрытии. Нативный details работает без JS. |
| Краткая проблема в карточке дословно повторяла раздел «Проблема», схема систем повторяла теги. | В `index.html` убраны три дублирующих абзаца; полный текст проблем сохранён в раскрытии. Схемы перенесены внутрь управляемого `aria-controls` блока. Название, системы и основной результат видны сразу. `contain-intrinsic-block-size` карточки уточнён с 540 до 380 px для компактного состояния. |
| Порог проверялся только на локальном компьютере с меняющейся скоростью CPU. | Добавлена `.github/workflows/lighthouse-mobile.yml`: чистый Ubuntu runner, закреплённый Lighthouse 13.5.0, тот же стандартный simulated Mobile/CPU ×4. CI ждёт точного совпадения опубликованных пяти файлов с коммитом и проверяет все десять холодных прогонов, сохраняет HTML/JSON каждого. Измеритель получил параметры путей Chrome/каталога отчётов для переносимости, проверку фактической темы по фону финального JPEG Lighthouse и сохранение этого скриншота после окончания измерения. |
| На новом runner первый запуск Chromium и загрузка Lighthouse происходили непосредственно перед первым аудитом. | Lighthouse импортируется до запуска измеряемого Chrome. Перед серией выполняется отдельная офлайн-проверка Chromium на data: HTML с системным шрифтом; её журнал подтверждает ноль HTTP-запросов. Затем браузер закрывается. Каждый из десяти аудитов приложения по-прежнему использует новый профиль; HTML/CSS/JS/Manrope/Geist заранее не запрашиваются браузером контрольной проверки. |
| chrome-launcher не дождался записи автоматически назначенного debugging port в stderr на CI. | `platform.cjs` и `measure.cjs` получают свободный loopback-порт от ОС и явно передают его Chrome. При ошибке платформенного запуска stderr сохраняется в артефакт. |

Закрытое содержимое уже имеет inert/aria-hidden. Отложенные видимые разделы сохраняют DOM и доступность при `auto`; механизм описан в [документации web.dev](https://web.dev/articles/content-visibility). Новых библиотек, сборки и внешних запросов нет.

## Методика

Lighthouse 13.5.0, Chrome 157, стандартный simulated mobile: RTT 150 ms, throughput 1638.4 Kbps, CPU ×4; четыре основные категории. Каждый прогон в отдельном временном профиле Chrome. Тема задаётся через localStorage при посещении favicon того же origin; приложение/шрифты заранее не загружаются. Storage reset отключён только ради сохранения темы. Движение не отключается. Замеры последовательные, без параллельных браузерных тестов. Это лабораторные оценки конкретного прогона, не полевые Core Web Vitals и не гарантия одинакового балла на любом компьютере.

Выпуск `17b3e72` также не прошёл публичный порог: [dark](release-production-dark.report.html) — 89/100/100/100, CLS 0.000964; [light](release-production-light.report.html) — 83/100/100/100, CLS 0. Эти файлы сохранены как промежуточные. [Подтверждение этого деплоя](release-deployment.json), [сверка файлов](release-files.json).

Последовательные диагностические локальные варианты (`font-navigation`, `final-layout`, `mobile-wrap`, `section-observers`, `closed-inspector`, `lazy-code`) сохранены, но не являются финальным подтверждением порога. Вариант обычного переноса текста не дал достаточного выигрыша и отклонён; `text-wrap:pretty/balance` сохранены. В [диагностике layout](layout-diagnostics.json) альтернативные CSS-правила применялись только браузерным route, не публиковались.

Полный текущий вариант локально: [dark](local-dark-deferred-cards.report.html) — 93/100/100/100, LCP 2.42 s, TBT 264 ms, CLS 0; [light](local-light-deferred-cards.report.html) — 91/100/100/100, LCP 2.42 s, TBT 271 ms, CLS 0. После замеров уточнена подготовка всех предшествующих карточек для длинных якорных переходов; стартовая загрузка без hash не менялась.

После последней правки повторно пройдены 18 адаптивных сценариев, пять ширин без JS, шесть проверок палитры/lightbox/вкладок и все 16 якорных сценариев. Дополнительно [четыре проверки с обычным движением](local-enhancement-checks.json): обе темы × 390/1440, отсутствие раннего построения схемы/слогана/вкладок, запуск при приближении, завершение счётчиков, раскрытие/повторное раскрытие кода без дублирования, клавиатурные вкладки и переключение reduce. Ошибок JS нет. Воспроизводимые скрипты: `verify-responsive.cjs`, `verify-utilities.cjs`, `verify-anchors.cjs`, `verify-enhancements.cjs` в этой папке; сетевые тесты не отправляют сообщений.

После публикации полного исправления обе темы измеряются заново на GitHub Pages; локальные оценки не заменяют этот этап. Вариативность лабораторных результатов и пользу повторных замеров описывает [Lighthouse](https://github.com/GoogleChrome/lighthouse/blob/main/docs/variability.md).

## Серия выпуска 1ff2530 и дополнительная правка

[Пять прогонов каждой темы](interim-series-results.json) на опубликованном `1ff2530`: dark Performance 82/84/93/88/89 (медиана 88), light 85/83/82/89/86 (медиана 85). Во всех десяти Accessibility/Best Practices/SEO 100 и CLS 0. Порог Performance не подтверждён. Все HTML/JSON сохранены под `interim-series-*`.

Скорость локального CPU по `environment.benchmarkIndex` изменилась с 1411.5 в исходном dark до 691.5 в первом прогоне этой серии. Чтобы отделить это влияние, добавлен отдельный CI runner; параметры замедления не ослаблены. Неудачные эксперименты с ранним показом панелей, удалением boot-статуса и наблюдателями по требованию отклонены и не публикуются. Диагностические статические копии без app JS удалены; их отчёты сохранены. Единственный DevTools-throttling прогон также диагностический (67), итоговый критерий остаётся simulated Mobile. Анонимный PageSpeed API вернул 429, публичный UI не смог получить страницу; оценок от него нет.

После компактного состояния кейсов локально: [dark](local-dark-compact-cases.report.html) — **95/100/100/100**, CLS 0, LCP 2.41 s, TBT 144 ms; [light](local-light-compact-cases.report.html) — **96/100/100/100**, CLS 0, LCP 2.41 s, TBT 86 ms. Дублирующий текст удалён, сами сведения остались в подробностях; функциональность не вырезана ради оценки.

Скриншоты отложенного профиля теперь ожидают `checkVisibility({contentVisibilityAuto:true})`, а не снимаются в первый кадр мгновенного программного скролла до завершения браузерной отрисовки. Обычная проверка анимаций также проверяет фактическую видимость профиля. CI ещё должен подтвердить опубликованный выпуск после этой правки.
