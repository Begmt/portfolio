## Изменения

| Before | After |
|---|---|
| Начальное сворачивание кейсов зависело от отложенного initCaseCards после DOMContentLoaded. До него браузер мог раскладывать подробное содержимое всех карточек. | В существующий head-скрипт добавлен класс `.js`, и стили закрытых кейсов применяются ещё до разбора body. Интерактивность/ARIA/inert кейсов инициализируются в основной стартовой группе. |
| Содержимое закрытых карточек оставалось участником работы отрисовки, хотя было свёрнуто и недоступно. | `.js .case-card:not(.expanded) .case-expand-inner` получает `content-visibility:hidden`. При раскрытии правило перестаёт действовать. |
| Браузер также рассчитывал дальние разделы до того, как они понадобятся посетителю. | Проекты, экосистема, сравнение процесса, ROI и workflow используют `content-visibility:auto` с приблизительными измеренными высотами и запоминанием реального размера через `auto`. Hero/кейсы/профиль/контакты не виртуализируются. В печати и без JS отложенная отрисовка этих секций отключена. |
| Изменение размеров отложенных секций влияло на расчёт длинного якорного перехода. | Перед переходом из навигации, палитры или по начальному hash подготавливаются секции до целевой включительно. Нативные hash/история и плавная прокрутка сохранены. |
| Без JS подробные кейсы должны оставаться видимыми. | Класс `.js` отсутствует при отключённом JS; полный контент остаётся доступным. Контент, метрики, дизайн, контакты и анимации не переписывались. |

Закрытое содержимое уже имеет inert/aria-hidden. Отложенные видимые разделы сохраняют DOM и доступность при `auto`; механизм описан в [документации web.dev](https://web.dev/articles/content-visibility). Новых библиотек, сборки и внешних запросов нет.

## Методика

Lighthouse 13.5.0, Chrome 157, стандартный simulated mobile: RTT 150 ms, throughput 1638.4 Kbps, CPU ×4; четыре основные категории. Каждый прогон в отдельном временном профиле Chrome. Тема задаётся через localStorage при посещении favicon того же origin; приложение/шрифты заранее не загружаются. Storage reset отключён только ради сохранения темы. Движение не отключается. Замеры последовательные, без параллельных браузерных тестов. Это лабораторные оценки конкретного прогона, не полевые Core Web Vitals и не гарантия одинакового балла на любом компьютере.

После публикации исправления обе темы будут измерены заново на GitHub Pages; локальные оценки не заменяют этот этап.
